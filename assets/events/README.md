# 活动图示素材目录

把处理好的活动图放在此目录，并在共享活动定义中配置 `image`：Version 5 使用 `lib/calendar-core.js`，Version 6 使用 `lib/version-six.js`。页面与公开 API 共用这些定义，不在 `app.js` 单独维护素材映射。

```js
image: "./assets/events/op-wander.webp",
```

页面会自动把这张图用于时间轴活动条、下方日程卡片和详情弹窗；公开 API 将它序列化为可访问的绝对 URL。没有配置 `image` 时，会继续显示现有的风格化图示。

## 建议规格

- 格式：优先 WebP，保留透明背景的素材可使用 PNG。
- 建议尺寸：横图 `1200 × 400`；只拿到角色立绘时可制作 `800 × 800` 透明底版本。
- 单张体积：尽量控制在 250 KB 以内。
- 构图：主体放在图片右侧，左侧保留暗色或透明空间，避免覆盖活动名称。
- 命名：使用日程 `id`，例如 `op-wander.webp`、`sanity-supply-first.webp`。
- 来源：优先使用官方公告封面、官方角色立绘或官方活动视觉；记录原始链接和发布日期，不建议从当前低清海报直接裁图。

## 新增素材流程

1. 确认素材可公开再分发，记录官方公告、原图链接、发布日期与授权依据；官方活动素材补入 [官方来源记录](./OFFICIAL_SOURCES.md)。
2. 按用途选择保留完整海报，或将允许裁切的封面、立绘制作成建议横图。完整海报不要截掉活动名称、日期或奖励说明。
3. 检查时间轴、日程卡片和详情弹窗中的构图与文字可读性；需要加工时保证主体清晰。
4. 导出 WebP，并压缩到建议体积。
5. 在共享活动定义的对应事件对象加入 `image` 字段，更新相关回归断言，在仓库目录运行 `npm test` 和 `npm run build`，并检查桌面端、移动端显示。
